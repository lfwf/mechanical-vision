# 新模型与内容审查流程

## 流程

```text
选题提案
→ 资料包建立
→ 工程母版/参数化模型
→ 模型自检
→ 内容编写
→ 独立模型审核
→ 独立内容审核
→ Web 集成
→ 自动验证
→ 集成审核
→ 预览
→ 正式发布
```

## 角色

### 作者

负责资料整理、模型或内容制作，并提交证据。作者不能批准自己负责的专业审核项。

### 模型审核人

核对几何、尺寸、装配、运动副、干涉、参数变化和模型简化。

### 内容审核人

核对定义、术语、公式、结论、来源、失效描述、维护内容和适用边界。

### 集成审核人

核对状态同步、交互、视觉、性能、移动端、无障碍和构建结果。集成审核不能替代机械专业审核。

## 质量档案

每个实验必须有：

```text
src/data/experiments/<experiment-id>.quality.json
```

质量档案是发布状态的唯一可信来源。页面徽标、审核面板和 CI 门禁均读取该档案。

## 发布门禁

执行：

```bash
npm run verify
```

包括：

1. 质量档案结构和来源映射检查；
2. 机械公式和参数范围检查；
3. TypeScript 严格检查；
4. 生产构建。

`released` 状态存在任何阻断项时，CI 必须失败。存在阻断项的内容只能保持 `preview`。

## 变更控制

以下变更必须重新审核：

- 关键几何公式；
- 模型比例、中心距、运动约束；
- 参数范围；
- 技术结论和公式；
- 失效、维护和安全边界；
- 来源版本；
- 精度等级；
- 从预览升级为正式发布。
